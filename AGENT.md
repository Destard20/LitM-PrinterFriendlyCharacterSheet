# AGENT.md

Guidance for AI coding agents (and humans) working on this repository.

## What this is
Printer-friendly and web-fillable sheets for the TTRPG *Legend in the Mist*, in English (`en/`) and Italian (`it/`):
- character sheet (hero sheet);
- action cards (9 trading-card-size cards per page, with cut lines);
- Fellowship card (IT: *Compagnia*), full page or 2 per page.

Each comes in A4 and Letter, with and without scratchmarks (`彡` in the checkboxes), plus a web-fillable HTML version. PDFs are published on GitHub and on itch.io.

## Golden rule: `en/` and `it/` are generated
Never edit files in `en/` or `it/` by hand: `build.py` overwrites them. Change the sources instead:
- layout: templates in `src/*.html` / `src/*.css`;
- wording: `src/lang/<code>.json` (every language file has the same keys);
- fonts: `src/fonts/` (fetched by `tools/fetch_fonts.py`; don't add fonts by hand).

Then rebuild and commit the sources **together with** the regenerated files and `pdf-manifest.json`.

## Commands
```
python3 build.py             # HTML only (fast; run after every change)
python3 build.py --pdf       # HTML + PDFs whose HTML changed
python3 build.py --pdf-all   # HTML + every PDF
python3 tools/publish_itch.py --dry-run   # what would go to itch.io
```
- Python 3, standard library only. Don't add dependencies.
- PDFs are printed by a headless browser: Chrome / Edge / Chromium / Brave if found (`LITM_BROWSER` to pick one), otherwise Firefox through `geckodriver`.
- `pdf-manifest.json` stores the SHA-256 of the HTML each PDF came from; `--pdf` reprints only what changed. If a print run dies halfway, just run it again.
- The build must finish with **no warnings**: unknown `{{key}}` is an error; unused language keys and leftover output files are warnings that mean something is out of sync.

## How the build works (`build.py`)
- `render(template, values, used)` fills `{{key}}` placeholders. Values come from the language JSON plus layout values computed by the script (paper size, `{{scratch}}`, cut lines, ...). `{{font_faces}}` is injected automatically. Keys read directly from `text[...]` in Python (e.g. PDF titles) must be added to `used`.
- `write()` writes an output file with a "Generated by build.py" comment.
- One `build_<sheet>()` per sheet type, called from `build_language()`. Each returns a list of `(html_path, pdf_path, paper)` to print. Web-fillable pages get no PDF.
- `PAPERS` holds the paper sizes (A4, Letter); `LINE_H` the writing-line height per paper.
- Language files: keys starting with `_` are metadata: `_code` (file-name code, e.g. `EN`), `_folder_sheet`, `_folder_cards`, `_folder_fellowship` (output folder names; translated, e.g. `Compagnia`).

### Output naming
- HTML: `<lang>/HTML/<folder>/LitM_<Sheet>_<CODE>_<Paper>[_2PerPage][_NoScratchmarks].html`, web: `LitM_WebFillable_<Sheet>_<CODE>_<Paper>.html`.
- PDF: `<lang>/PDF/<folder>/<title from the language file> (<Paper>[, <variant>][, No Scratchmarks]).pdf`.
- `tools/publish_itch.py` and the README rely on these names; update them together.

### Adding a sheet
Follow `build_fellowship` as the newest example: printable page shell (`fellowship.html`) + content fragment (`fellowship_spread.html`), web variant reusing the shell with a `{{web_css}}` slot (`fellowship_web.css`, `fellowship_web_spread.html`). Add the language keys to **every** `src/lang/*.json`, add a `_folder_*` key if it gets its own folder, then update the README structure table and, if it should be on itch, `channels()` in `tools/publish_itch.py`.

## Styling conventions
- Fonts are embedded (EB Garamond for text, `'LitM Symbols'` for ♦ ▽ ☘ ⚔ ♛ ✂, `'LitM Scratch'` for 彡), so sheets look the same everywhere. Any new symbol must exist in those font subsets: check with `pdffonts` that nothing falls back to a system font.
- Same look across sheets: thick rounded `.box` borders with the `.box-title` sitting on the border (white background patch), ♦ power tags with scratch boxes, ▽ weakness tags without boxes, circle tracks.
- Print CSS: `@page { size: …; margin: 0 }`, `print-color-adjust: exact`, and a fixed `.page` height in mm with `overflow: hidden` (otherwise rounding spills a blank extra page).
- Don't put `overflow: hidden` on a `.box`: it clips the title on the border. Clip an inner wrapper instead (see `.ruled`).
- Web-fillable pages: transparent inputs over the printed lines, `::placeholder` hidden in print, checkboxes styled with `appearance: none`.

## Checking your work
Visual checks matter more than anything else here. After a layout change:
1. `python3 build.py --pdf`, no warnings.
2. `pdfinfo` → 1 page per sheet (2 for the character sheet), size 596×842 pt (A4) or 612×792 pt (Letter).
3. `pdffonts` → every font embedded.
4. `pdftoppm -r 70 -png <pdf> <prefix>` and look at the images: titles on borders, nothing clipped, cut lines in place, Italian text not cut off (Italian strings are usually longer).
5. For web-fillable pages, fill some fields (e.g. via geckodriver's WebDriver API) and print to check text sits on the lines.

Put screenshots/scratch files in a folder you delete afterwards; don't commit them.

## Automation
- `.github/workflows/build.yml` runs on pushes to `main` touching `src/**`, `build.py`, `tools/publish_itch.py` or the workflow, and on manual dispatch. It runs `build.py --pdf`, commits regenerated files as `github-actions[bot]` (so `git pull` before pushing again), then on `main` uploads to itch.io with butler (`BUTLER_API_KEY` secret).
- itch.io (`destard20/litm-printerfriendlysheets`): the English PDFs with scratchmarks get one channel each; each language's HTML goes in one zip channel (`en-html`, `it-html`) with a `contents.txt` listing the files. Uploads use butler's `--if-changed`, which **does not notice newly added files** on its own; `contents.txt` exists to make additions count. If a channel ever seems stale, run the workflow by hand with **force_itch**.
- Channel names must not contain OS words (`win`, `linux`, `mac`, `osx`, `android`): itch would tag the download as a game for that OS. `check()` enforces this.

## Language notes
- Italian names used so far: Scheda del Personaggio, Carte Azione, Carta Compagnia (Fellowship), Missione (Quest), Abbandono / Miglioria / Avanzamento (Abandon / Improve / Milestone), Miglioramenti Speciali, Note.
- Keep game terms consistent with the existing language files rather than translating afresh.
